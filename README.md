# Instagram Auto Post

포스텔러 [오늘의 운세 이미지 페이지](https://event.forceteller.com/outsourced)에서 매월 다음 달 띠별·별자리 운세 이미지를 준비하고, Supabase 비공개 Storage에 보관합니다. 트위터 탭은 사용하지 않습니다.

## 월별 이미지 준비

GitHub Actions의 `Import next month's fortune images`가 한국시간 **매월 1일 09:00**에 실행됩니다. 첫날 사이트나 네트워크 오류가 있었다면 **2일 09:00**에 다시 시도합니다. 재시도는 누락된 파일만 채우며 이미 있는 이미지를 덮어쓰지 않습니다.

- 사이트에서 '다음 달' 띠별 운세 ZIP과 별자리 운세 ZIP을 각각 내려받습니다.
- 날짜·분류·이미지 개수(월 일수 × 2)·PNG 형식·1080×1350 크기를 확인합니다.
- `insta-images/YYMM/MMDD{A|B}.png`에 저장합니다. A는 띠별, B는 별자리입니다.
- 예: 2026년 11월 1일 → `2611/1101A.png`, `2611/1101B.png`.
- 성공 또는 실패는 기존 Slack 웹훅으로 알립니다.

이미 60장이 들어 있으면 사이트를 다시 내려받지 않고 종료합니다. 부분 업로드가 중단되어도 다음 실행에서 누락분만 채웁니다. 사람이 기존 파일을 고쳐 올린 경우 그 파일은 유지됩니다.

수동 점검은 Actions → `Import next month's fortune images` → Run workflow에서 `dry_run`을 켜고 실행합니다. 이 경우 두 ZIP을 실제로 내려받고 검사하지만 업로드하지 않습니다. 수동 실행에서 `dry_run`을 끄면 다음 달 누락 파일을 즉시 채웁니다.

### macOS 러너를 쓰는 이유

사이트는 '전체 이미지 다운로드' 때 브라우저 안에서 PNG를 그리며, 웹폰트를 넣지 않고(`skipFonts`) 시스템 글꼴을 씁니다. 그래서 결과가 OS마다 다릅니다. Ubuntu에서는 더 넓은 Noto CJK로 그려져 글자가 칸 밖으로 잘리고, macOS에서는 Apple SD Gothic Neo로 그려져 기존에 준비한 이미지와 같습니다(2026-10-01 대조: 11월 60장 모두 평균 차이 ≤ 0.10). 이 워크플로는 `macos-latest`에서 실행합니다.

### 기존 이미지 원본 대조 (읽기 전용)

Run workflow에서 `dry_run`과 `verify_existing`을 함께 켭니다. 다음 달 ZIP을 받아 Supabase의 같은 경로 파일과 축소 흑백 이미지로 비교하고, 날짜·종류별 수치를 로그에 남깁니다. 다른 날짜 이미지는 평균 약 10 / 변화 픽셀 약 9%, 한 줄만 달라도 약 0.15%라서 기준(평균 0.5, 변화 0.03%)을 넘으면 `11/3 별자리(B)`처럼 알립니다. 1일자 원본·저장본과 불일치 파일은 `comparison-samples` 아티팩트(7일 보관)로 남습니다. 파일은 바꾸지 않습니다.

### Slack 알림 예

- `✅ 2026-12 운세 이미지: 신규 업로드 62장, 기존 유지 0장 → 2612/ 에 62/62장 확인`
- `✅ 2026-12 운세 이미지: 신규 업로드 0장 — 2612/ 에 62장(...)이 이미 모두 있음 ...`
- 2일 예약 실행은 `[2일 재확인]`, 수동 점검은 `[점검 실행·업로드 안 함]` 표시가 붙습니다.
- `❌ 2026-12 운세 이미지 준비 실패: <원인>` (사이트에 다음 달이 아직 없음, ZIP 개수 부족, 손상 의심 기존 파일, 업로드 후 누락 등)

기존 파일이 100KB 미만이거나 PNG가 아니면 덮어쓰지 않고 실패로 알립니다. 규칙 밖 파일명이 폴더에 있으면 ⚠️로 표시합니다.

## 매일 게시

별도의 Supabase Cron이 `Instagram Auto Post` 워크플로를 실행합니다.

- A: 운세 날짜 전날 21:05 KST
- B: 운세 날짜 전날 21:35 KST

게시 프로그램은 비공개 PNG를 RGB JPEG로 변환해 Meta가 접근할 임시 공개 주소로 전달한 뒤 임시 파일을 삭제합니다. 게시가 성공하면 `_published-v2/YYYY-MM-DD-{A|B}.json`에 기록되어 정규 중복 게시를 막습니다.

## 이미지 오류 시 교체·재발행 절차

1. 인스타그램 앱에서 잘못된 게시물을 **보관**합니다(삭제 아님).
2. Supabase `insta-images/YYMM/MMDD{A|B}.png`를 올바른 PNG로 교체합니다. 월별 준비 작업은 기존 파일을 덮어쓰지 않으므로 교체본이 유지됩니다. 교체 전에 `verify_existing` 점검으로 원본과 비교할 수 있습니다(다음 달 파일만 가능).
3. `Instagram Auto Post`를 `target_date`·`slot` 지정, `dry_run` 켬으로 먼저 실행해 이미지·계정을 확인합니다.
4. 실제 재발행은 현재 `dry_run` 끔 + `test_publish` 켬으로 실행합니다. 이 방식은 `_published-v2` 기록을 바꾸지 않으므로(기록에는 보관된 이전 게시물 ID가 남음) **반드시 정규 게시 시각이 지난 날짜에만** 쓰고, 버튼을 한 번만 누릅니다. 아직 정규 게시 전인 날짜에 쓰면 예약 게시와 중복됩니다.
5. 일회성 워크플로 파일을 따로 만들 필요는 없습니다.

## 지난 운세 피드 정리 (수동)

Instagram 공식 API(Graph API)는 게시물 순서 변경·고정·보관을 지원하지 않습니다. 게시물 수정 API는 댓글 켜기/끄기만, 그 외에는 삭제만 있습니다. 운세 날짜가 지난 게시물(예: 28일 운세 → 29일 00:00 KST 이후)을 아래로 내리는 작업은 아이폰 인스타그램 앱에서 직접 해야 합니다. 비공식 자동화는 계정 제재 위험이 있어 쓰지 않습니다.

## GitHub Actions Secrets

- `INSTAGRAM_ACCESS_TOKEN`
- `SUPABASE_URL`
- `SUPABASE_SECRET_KEY`
- `SUPABASE_BUCKET` (현재 `insta-images`)
- `SLACK_WEBHOOK_URL`

인스타그램 토큰은 기존 게시 프로그램이 7일마다 갱신하고, 비공개 Supabase의 `_config/instagram-token.json`에 저장합니다.
